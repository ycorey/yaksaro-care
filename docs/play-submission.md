## 2. 스토어 등록정보

### 설명 첫 문단 — 비의료기기 고지 (필수)
Play 건강앱 정책은 규제 승인이 없는 앱에 이 고지를 **설명 첫 문단에** 요구한다.
없으면 업데이트가 리젝된다. 약 지갑 하단(`@wallet/default.tsx`)과 글자 단위로 같은 문구를 쓴다(설정 화면은 '복용 여부와 방법에 대한' 이 덧붙은 변형).
정책 원문은 "설명 안" 고지를 요구하며 첫 문단 배치는 우리 기준이다(`play-store-listing.md`).

> 약사로케어는 의료기기가 아닙니다. 질병의 진단·치료·예방에 사용할 수 없고,
> 등록된 정보로 질병 유무를 판단하지 않습니다. 판단이 필요하면 약사·의사와 상담해 주세요.

### 설명문 자가검수

⚠️ 단어 단위로 훑지 말 것. `진단·치료·예방` 은 **필수 고지문 자체가 쓰는 말**이다
("질병의 진단·치료·예방에 사용할 수 **없고**"). 부정문까지 걸러내면 요건을 스스로 지운다.
걸러야 하는 것은 **효능을 주장하거나 없다고 단언하는 문장**이다.

금지 — 효능 주장: 「~을 치료합니다 / 진단합니다 / 예방합니다 / 완치 / 개선 효과 / ~에 좋습니다」

　　　　　　　　　검출되지 않았습니다 / 부작용이 없습니다」
금지 — 행동 지시: 「복용을 중단하세요 / 처방을 바꾸세요 / 용량을 줄이세요」
허용 — 부정문 형태의 면책: 「의료기기가 아닙니다 / 진단·치료·예방에 사용할 수 없습니다 /

### 왜 약사 화면을 앱에서 못 뺐는가
manifest `scope` 는 **단일 경로 접두사**인데 환자 화면이 루트 전역에 흩어져 있어
(`/home` `/wallet` `/today` `/settings` `/medications` …) `/pharmacy` 만 제외하는 접두사가 없다.
그리고 **웹 배포 = 앱 갱신**이라 앱에서 지우면 웹에서도 지워진다.
display-mode 로 막으면 PWA 를 설치한 **약사**가 대신 막힌다.
→ 현실적 대응은 심사 메모에 두 역할을 설명하는 것이다. 분리하려면 별도 서브도메인이 필요하다.
