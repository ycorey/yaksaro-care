# 약 정보·생활관리 정보 가독성 — 설계

작성 2026-08-28 · 상태: 승인됨(구현 계획 대기)

## 문제

두 화면 모두 **한 단위당 850~900자**가 한 번에 펼쳐진다. 390px 화면에서 3~5 스크롤이라 실버 사용자가 읽기를 포기한다.

**약 정보** — 약 지갑에서 "이 약은 어떤 약인가요?"를 펼쳤을 때 나오는 6필드 패널(`@wallet/med-card-item.tsx`). 캐시 실측(`drug_summaries`, n=6):

| 필드 | 평균 | 최대 |
|---|---|---|
| 효능·효과 | 77 | 119 |
| 복용법 | 98 | 196 |
| 주의사항 | **272** | **370** |
| 상호작용 | 99 | 152 |
| 부작용 | **268** | **535** |
| 보관법 | 41 | 46 |
| **합계** | **855** | |

길이의 대부분이 주의사항·부작용이다. 표본이 6행뿐이라 대표성은 약하지만, 두 필드가 지배적이라는 구조는 실화면(페니라민정)에서도 확인된다.

**생활관리 정보** — `lifestyle_content` 9행(질환 3 × 주제 3), 본문 평균 287자·최대 377자, 항목당 출처 5개. 질환 하나에 리드 문장 + 카드 3장이니 **약 900자**, 추정 질환이 3개면 2,700자가 한 번에 렌더된다(`@wallet/lifestyle-section.tsx`는 접기 없는 서버 컴포넌트).

## 결정

두 콘텐츠는 성격이 반대라 같은 해법을 쓰지 않는다.

**약 정보는 식약처 원문이다 → 표시 계층에서만 줄인다.**
주의사항 길이의 대부분은 **금기 대상 목록**이다. 실제 원문(페니라민정):

> …과민증 환자, 녹내장, 전립선비대 등 하부요로폐색성 질환, 미숙아 및 신생아는 **이 약을 복용하지 마십시오.** 3세 미만 유아, 임부 및 수유부, 고령자, 안내압 상승, 갑상샘기능항진, … 발작 환자는 **의사 또는 약사와 상의하십시오.** 복용 후 졸음을 유발할 수 있으므로 운전 및 기계조작 시 **주의하십시오.**

LLM으로 줄이면 이 목록에서 항목이 빠진다. 약 설명에서 **누락은 추가만큼 위험하다** — "녹내장"이 빠진 요약을 녹내장 환자가 읽는 상황이 된다. 그래서 원문 글자는 건드리지 않는다.

**생활관리 정보는 우리가 생성한 것이다 → 생성 시점에 요약을 함께 만든다.**
`gen-lifestyle-content.mjs`가 Anthropic SDK로 본문·출처·근거등급을 만든다. 원문 훼손 개념이 없고, 잘라낸 첫 문장보다 목적을 갖고 쓴 2문장이 읽힌다. 전문은 남기고 한 번 더 눌러서 본다.

## 설계 A — 약 정보

### 신규 순수 모듈 `src/lib/drug-text.ts`

```
splitSentences(text: string): string[]
groupCautions(sentences: string[]): { prohibit: string[]; consult: string[]; caution: string[] }
```

**문장 분리**: 마침표 앞 음절이 한국어 종결형(`다`·`요`·`오`)일 때만 자른다. 관찰된 종결형은 `…마십시오.` `…상의하십시오.` `…주의하십시오.` `…사용합니다.` `…있습니다.` 로 전부 이 셋에 들어간다. 마침표 전부를 기준으로 자르면 `1일 5회(75 mg/kg)`·`3.0~3.7` 같은 소수·용량 표기가 문장을 쪼갠다. 개행도 분리자로 본다.

**분류**: 문장 어미로만 판정한다 — `복용하지 마십시오`·`투여하지 마십시오`·`금기` → `prohibit` / `상의하십시오`·`상담` → `consult` / 그 외 → `caution`. 의미 해석이 아니라 어미 매칭이라 결정론적이다.

두 함수 모두 순수 함수이고 **원문 문장을 고르고 재배열만** 한다. 글자를 바꾸지 않으므로 변조도 누락도 구조적으로 불가능하다.

### 패널 렌더 변경

기본으로 펼쳐 두는 것: **효능·효과 · 복용법 · 보관법**(합 216자) + 상호작용(99자). 1스크롤 이내다.

접는 것: **주의사항 · 부작용**. 접힌 라벨에 건수를 단다 — "복용 전 확인할 것 4가지", "알려진 부작용 6가지". 펼치면 문장 목록이 나오고 `prohibit` 그룹이 맨 위로 온다.

접기는 `<details>`/`<summary>`를 쓴다. 상태도 JS도 필요 없고 스크린리더·키보드 지원이 기본이다. `<summary>`에 `min-h-[44px]`로 터치 타겟을 맞춘다.

**폴백**: `splitSentences()` 결과가 2개 미만이면 분리에 실패한 것이므로 **원문을 통째로 표시**한다. 잘린 문장을 보여주는 것보다 긴 편이 낫다.

기존 출처·상담 푸터(`자료: 식품의약품안전처 · 정확한 판단은 담당 약사와 상담하세요`)는 그대로 둔다.

## 설계 B — 생활관리 정보

### 마이그레이션 `069_lifestyle_summary.sql`

```sql
alter table public.lifestyle_content add column if not exists summary_ko text;
```

### 생성기 `scripts/gen-lifestyle-content.mjs`

본문과 **같은 호출에서** 요약을 함께 받는다(추가 호출 없음). 요약 제약: 2문장 이내·100자 내외·본문에 없는 사실을 넣지 않음·기존 안전 프레임(질환군 주어, 개인 지시 없음) 유지. 9행뿐이라 재생성 비용이 작다.

### 읽기 게이트 `src/lib/lifestyle-info/server.ts`

현재 `passesSafetyFrame(body_ko)`로 본문을 거른다. **요약도 같은 게이트를 통과해야 채택**하고, 실패하면 `summaryKo: null`로 둔다. 그 경우 카드는 기존처럼 본문을 보여준다 — 요약이 게이트에 걸렸다고 정보 자체가 사라지면 안 된다.

```ts
export type LifestyleTip = {
  disease: string; topic: string; body_ko: string
  summary_ko: string | null   // 게이트 통과분만. null 이면 본문 표시
  sources: LifestyleSource[]
}
```

### 렌더 `src/app/(main)/@wallet/lifestyle-section.tsx`

`summary_ko`가 있으면 카드 기본은 **요약 + 근거 배지**, `<details>`로 펼치면 전문과 출처 링크. 없으면 지금과 동일하게 본문을 편다.

`<details>`를 쓰는 이유는 **서버 컴포넌트를 유지**하기 위해서다. 클라이언트 컴포넌트로 바꾸면 번들과 하이드레이션이 늘고, 성능 기준("무겁고 조건부인 클라 컴포넌트는 dynamic")과도 어긋난다.

## 검증

**Unit** (`npm run test:unit`)
- `src/lib/drug-text.test.ts` — 페니라민정 실제 주의사항 원문을 픽스처로 고정
  - 문장이 3개로 분리되고 각각이 온전한 문장이다
  - `prohibit` 문장이 맨 위로 온다
  - **재조립하면 원문 문장 집합과 정확히 같다**(누락·변조 0 회귀 가드)
  - 용량 표기(`1일 5회(75 mg/kg)`)·소수(`3.0~3.7`)에서 자르지 않는다
  - 분리 실패 시 원문 1개를 그대로 돌려준다

**Integration/E2E** — `e2e/wallet-signal-qa.mjs` 확장
- 패널 기본 상태에 **부작용 본문이 렌더되지 않는다**(접힘 확인)
- `<summary>` 클릭 후 원문 전체가 보인다
- `<summary>` 터치 타겟 ≥ 44px
- 생활관리: `summary_ko`가 게이트에 걸린 행에서 본문이 표시된다(폴백)

**금칙어 스캔의 적용 범위** — 이 화면에서는 스캔 대상을 **앱이 쓴 문구로 한정**한다(접기 라벨·건수 라벨·푸터). 원문 인용 블록은 제외한다. 식약처 원문에는 용량 수치(`1일 5회(75 mg/kg)`)와 `복용하지 마십시오`가 정당하게 들어 있고, 그것을 그대로 보여주는 것이 이 설계의 목적이기 때문이다. 앱이 그 말을 **하는 것**과 원문을 **인용하는 것**은 다르다. 구현 시 원문 블록에 `data-quoted="mfds"`를 달아 스캔에서 제외한다.

## 짚어둘 것

**마이그레이션 번호**: 상호작용 계획서(`plans/linear-knitting-simon.md`)가 Phase 5에 069를 배정해 뒀다. 이 작업이 먼저 나가면 069를 가져가고 DUR flag types 확장은 **070**으로 밀린다.

**표본 한계**: `drug_summaries`가 6행뿐이라 필드 길이 평균은 대표성이 약하다. 다만 "주의사항·부작용이 지배적"이라는 구조는 실화면으로 확인됐고, 설계가 그 구조에만 의존하므로 표본이 커져도 결론은 바뀌지 않는다.
