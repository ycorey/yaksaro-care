# 약사 보드 — 할 일 일자별 스케줄 관리

**작성일:** 2026-08-12 · **대상:** `/pharmacy` 대시보드

## 문제

약사 보드의 "오늘 할 일"은 두 종류가 섞여 있다.

- **자동 파생** (`deriveTodayAutoTasks`) — 답장 대기 · 오늘 마감 · 오늘 리필. 요청·리필 데이터에서 계산하며 항상 "오늘" 기준이다.
- **수동 메모** (`pharmacy_todos`) — **날짜 필드가 없다.** `created_at` 만 있어서 한 번 적으면 완료할 때까지 목록에 남는다.

그래서 어제 적은 메모와 오늘 적은 메모가 같은 "오늘 할 일" 목록에 구분 없이 섞인다. 사용자 표현으로 **"오늘 할 일인데 그 오늘이 언제인지 구분할 수가 없다."**

캘린더(`PharmacyCalendar`)는 이미 있지만 요청 마감일·리필일만 보여줄 뿐 할 일과 연결돼 있지 않다. 날짜를 눌러도 그날 할 일이 뜨지 않는다.

## 설계

### 1. 데이터 — `pharmacy_todos.due_date`

마이그레이션 `056`:

- `due_date date not null` 추가
- 기존 행은 `created_at` 의 **KST 날짜**로 백필
- 인덱스 `(pharmacy_id, due_date, done)`

날짜 값은 **앱이 KST 기준으로 명시해 보낸다.** DB 기본값(`current_date`)은 UTC 기준이라 KST 밤 9시 이후 하루가 어긋난다. 이 코드베이스는 이미 `todayKST()` 를 쓰고 있으므로 그 기준을 따른다. 컬럼 기본값은 안전망으로만 둔다.

### 2. 화면 — 캘린더 선택을 할 일 패널이 따라간다

`PharmacyCalendar` 는 이미 `sel` 상태(기본값 오늘)를 갖고 선택 날짜의 항목을 보여준다. 이 상태를 부모(`page.tsx` → 클라이언트 래퍼)로 끌어올려 할 일 패널이 같은 날짜를 보게 한다.

선택한 날의 할 일:

| 구분 | 출처 |
|---|---|
| 자동 | 그날 마감인 요청 · 그날 리필 (기존 `buildCalendarItems` 재사용) |
| 수동 | `pharmacy_todos.due_date = 선택날` |

메모를 추가하면 **선택한 날짜에** 저장된다. 패널 헤더가 `8월 12일 (수) 할 일` 처럼 날짜를 말한다 — 이것이 문제 해소의 핵심 지점이다.

### 3. 밀린 일

선택한 날이 **오늘일 때만**, `due_date < 오늘 && !done` 인 메모를 `밀린 일 (2)` 로 목록 맨 위에 묶는다. 각 항목에 원래 날짜(`8/10`)를 붙인다.

**날짜는 바꾸지 않는다.** 언제 하려던 일이었는지가 남아야 다음 일정을 잡을 때 판단이 선다. 자동으로 오늘로 끌어오면 목록은 깨끗해지지만 그 기록이 사라진다.

### 4. 범위 밖 (YAGNI)

반복 일정 · 알림 · 담당자 배정은 넣지 않는다. 1인 약국에 지금 필요한 것은 "이 메모가 언제 할 일인가"이지 일정 관리 도구가 아니다.

자동 파생 항목은 원본(요청 `due_date`, 리필일)이 이미 날짜를 갖고 있으므로 저장 구조를 바꾸지 않는다. '답장 대기'는 날짜에 매이는 성격이 아니라 오늘 화면에만 유지한다.

## 검증

- 마이그레이션 후 백필 결과를 운영 DB 로 확인(기존 행에 `due_date` 가 채워졌는지)
- e2e: 어제 날짜 메모를 시드 → 오늘 화면에서 `밀린 일` 로 뜨고, 어제를 선택하면 제자리에 뜨는지
- `pharmacist-rls-qa` 회귀 — 메모는 약국 owner 전용이라 정책 변화가 없어야 한다
- `tsc` · `lint` · `build` · unit · E2E

## 결정 기록

- **밀린 일을 오늘에만 묶는다** — 과거 날짜를 볼 때도 밀린 일을 얹으면 "그날 무엇이 있었나" 를 볼 수 없게 된다. 과거 조회는 기록 확인 용도다.
- **캘린더를 새로 만들지 않는다** — 이미 날짜 선택 UI 가 있고 요청·리필을 표시한다. 새 위젯을 만들면 같은 정보가 두 곳에 생긴다.
